完整操作教學怎麼做？

直接答案： 完整操作從確認工具與資料結構開始，再依序設定規則、產出結果、測試例外並人工驗收。每一步都要保留可核對的輸入與輸出。

步驟 1：建立測試副本與成功條件

先複製原始檔，或建立只含欄位標題與三筆假資料的測試表。寫下「完成後應看到什麼」，例如公式回傳數字、試算表新增一列、雲端硬碟出現指定檔案，或 Dashboard 顯示可回扣的 KPI。

步驟 2：確認資料欄位與型態

逐欄核對工作表名稱、欄位標題、日期、文字、數字與唯一鍵。不要只依投影片中的欄位字母，因為實際檔案插入或刪除欄位後，位置可能不同。

步驟 3：依序完成核心工作

  1. 建立商品清單與訂單工作表。
  2. 定義自動訂單編號、時間與付款預設值。
  3. 請 AI 產生 Code.gs 與 Index.html。
  4. 從試算表讀取商品與單價。
  5. 部署為網頁應用程式。
  6. 用測試訂單檢查寫入與計算。

步驟 4：貼入完整 Prompt 並補上自己的資料位置

先把下方 Prompt 中的工作表名稱、欄位、網址、Spreadsheet ID、文件樣板、Email 或 MENU 替換成自己的測試資料。若需求涉及 Apps Script，要求輸出完整的 Code.gs 與 Index.html，不能只拿片段程式碼。

步驟 5：先小量執行，再擴大範圍

公式先用三至五筆資料測試；Apps Script 先用副本與自己的測試信箱執行；Web App 先送出一筆測試資料。確認結果正確後，再換成完整資料範圍。

步驟 6：依驗收清單核對與記錄例外

至少保留一個正常案例、一個邊界案例與一個錯誤案例。若結果不符，回頭檢查欄位名稱、資料型態、日期範圍、唯一鍵、權限與部署版本。

可直接複製的完整 Prompt

直接答案： 以下 Prompt 依投影片的六句提示法補齊目的、使用者、欄位、功能、規則與畫面或輸出。複製前必須替換自己的資料位置與測試條件。

① 我要做什麼
我要做一個「SnackFlow 經銷商訂購 Web App」，讓經銷商透過網頁填寫訂單，並將訂單自動寫入 Google 試算表「SnackFlow 訂單總表」。
② 給誰使用
給 SnackFlow 經銷商填寫訂單；營運主管透過試算表統一查看與管理。
③ 有哪些欄位
欄位包含訂單編號、付款時間、幣別、付款狀態、優惠代碼名稱、優惠代碼、商品名稱、品牌、商品分類、口味類型、植物性、購買數量、推估單價、金額。訂單編號與時間由系統產生；下拉選項從「訂單總表」、「商品清單」與「幣別」工作表讀取。
④ 要哪些功能
自動產生訂單編號與付款時間；讀取下拉選單；依商品名稱帶入單價；依數量×單價計算金額；送出後寫入訂單總表並顯示成功訊息；防止重複送出。
⑤ 有哪些規則
訂單編號格式為「SNK-年月-流水號」；付款狀態預設「待付款」；幣別讀取「幣別」A 欄；選項去除重複；商品與單價以伺服器端資料為準；金額不可由使用者輸入；必要欄位需驗證；不要加入線上付款。
⑥ 畫面風格
做成簡潔、清楚、適合手機與電腦快速下單的頁面。請提供完整 Code.gs 與 Index.html，說明新增檔案、授權、部署、執行身分、存取權限、版本更新，以及送出一筆測試訂單的逐項驗收。

Q如何使用這份 Prompt？

  1. 保留六個區塊，不要只複製第一句。
  2. 把範例中的工作表、欄位字母、網址、ID、Email 與日期換成測試資料。
  3. 要求先說明假設，再輸出公式或完整程式碼。
  4. 執行前檢查是否會寄信、分享檔案、覆寫資料或建立公開網址。
  5. 把錯誤訊息與預期結果一起回填，要求只修正受影響部分。

如何驗收結果？

直接答案： 驗收不能只確認公式沒有錯誤或程式成功執行，還要核對資料範圍、計算規則、例外案例、輸出內容與必要權限。

  • 商品下拉選單來自商品清單。
  • 單價不可由外部使用者任意修改。
  • 金額等於數量乘以單價。
  • 重複送出與缺漏欄位有處理。

建議再做三層核對：第一層用兩至三筆資料手算；第二層比較來源總筆數與輸出總筆數；第三層測試空白、重複、未對應、期間外或權限不足等例外。

常見錯誤與限制有哪些？

直接答案： 最常見問題是欄位與指標未定義清楚、直接相信產出，以及忽略資料型態、權限、部署版本與工具規模限制。

  • 把 Code.gs 與 Index.html 貼在同一檔案。
  • 修改程式後沒有重新部署新版本。
  • 將知道連結的任何人等同於安全身分驗證。

若工作涉及正式財務、法遵、薪資、交易、大量多人使用或高可用性要求，應加入正式審核、權限、測試、記錄與稽核機制，不能只依賴教學用試算表原型。

常見問題 FAQ

直接答案： 以下問答處理操作、驗證與工具選擇時常見的疑問；每個答案都可脫離前文單獨閱讀與套用。

QApps Script 可以建立網頁訂貨表單嗎？

可以使用 HtmlService 建立前端頁面，透過 Apps Script 後端讀寫 Google 試算表。

Q修改程式後為什麼網頁還是舊的？

Apps Script Web App 通常需要建立新版本或更新部署，單純儲存程式不一定會更新公開網址內容。

Q執行身分應該選誰？

若程式需要寫入擁有者的試算表，常由擁有者身分執行；實際設定需依資料權限與組織政策決定。

Q知道連結的任何人可以使用安全嗎？

這只是存取方式，不是完整身分驗證。敏感訂單或個資應限制帳號、加入驗證或改用正式系統。

Q可以加入線上付款嗎？

技術上需要串接付款服務，但不建議用簡單 Apps Script 原型直接處理敏感付款資料。
