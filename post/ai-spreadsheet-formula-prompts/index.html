SnackFlow 遇到了什麼工作問題？

SnackFlow 營運人員需要算出指定商品的已付款營收，並一次列出各品牌銷售數量。營運人員沒有只問「幫我寫公式」，而是交代付款狀態、商品名稱、品牌、數量與金額所在欄位，請 AI 分別提供 SUMIFS 與 QUERY 做法。

完整操作教學怎麼做？

直接答案： 完整操作從確認工具與資料結構開始，再依序設定規則、產出結果、測試例外並人工驗收。每一步都要保留可核對的輸入與輸出。

步驟 1：建立測試副本與成功條件

先複製原始檔，或建立只含欄位標題與三筆假資料的測試表。寫下「完成後應看到什麼」，例如公式回傳數字、試算表新增一列、雲端硬碟出現指定檔案，或 Dashboard 顯示可回扣的 KPI。

步驟 2：確認資料欄位與型態

逐欄核對工作表名稱、欄位標題、日期、文字、數字與唯一鍵。不要只依投影片中的欄位字母，因為實際檔案插入或刪除欄位後，位置可能不同。

步驟 3：依序完成核心工作

  1. 說明使用 Excel 或 Google 試算表。
  2. 列出工作表名稱、欄位名稱與資料型態。
  3. 說明篩選條件與加總欄位。
  4. 要求提供單一結果與完整彙總兩種做法。
  5. 要求逐段解釋公式。
  6. 貼回試算表並抽查兩至三筆。

步驟 4：貼入完整 Prompt 並補上自己的資料位置

先把下方 Prompt 中的工作表名稱、欄位、網址、Spreadsheet ID、文件樣板、Email 或 MENU 替換成自己的測試資料。若需求涉及 Apps Script，要求輸出完整的 Code.gs 與 Index.html，不能只拿片段程式碼。

步驟 5：先小量執行，再擴大範圍

公式先用三至五筆資料測試；Apps Script 先用副本與自己的測試信箱執行；Web App 先送出一筆測試資料。確認結果正確後，再換成完整資料範圍。

步驟 6：依驗收清單核對與記錄例外

至少保留一個正常案例、一個邊界案例與一個錯誤案例。若結果不符，回頭檢查欄位名稱、資料型態、日期範圍、唯一鍵、權限與部署版本。

可直接複製的完整 Prompt

直接答案： 以下 Prompt 依投影片的六句提示法補齊目的、使用者、欄位、功能、規則與畫面或輸出。複製前必須替換自己的資料位置與測試條件。

① 我要做什麼
我要分析 Google 試算表「訂單總表」的銷售數量，先計算商品名稱為「Oreo Original」且付款狀態為「已付款」的總購買數量，再一次統計每個品牌的總購買數量。
② 給誰使用
給 SnackFlow 的營運主管、行銷企劃或需要分析銷售資料的人使用，不需要撰寫程式，只透過 Google 試算表公式完成。
③ 有哪些欄位
資料來源為「訂單總表」，付款狀態在 E 欄、商品名稱在 G 欄、品牌在 I 欄、購買數量在 L 欄。請先提醒我核對實際欄位位置，若我的檔案不同就依標題調整。
④ 要哪些功能
提供一條 SUMIFS 公式計算指定商品的已付款總購買數量；再提供一條 QUERY 公式，一次列出每個品牌的已付款總購買數量並由高到低排序；用白話逐段解釋兩條公式與適用情境。
⑤ 有哪些規則
指定商品計算必須同時符合「付款狀態＝已付款」與「商品名稱＝Oreo Original」；品牌統計需自動分組；新增資料後結果要能更新；若地區設定使用分號，請另給分號版本。
⑥ 畫面與驗收
結果直接顯示在 Google 試算表，不另做介面。請提供三筆人工驗算方法，並提醒檢查標題列、空白、文字數字型態與整欄引用。

Q如何使用這份 Prompt？

  1. 保留六個區塊，不要只複製第一句。
  2. 把範例中的工作表、欄位字母、網址、ID、Email 與日期換成測試資料。
  3. 要求先說明假設，再輸出公式或完整程式碼。
  4. 執行前檢查是否會寄信、分享檔案、覆寫資料或建立公開網址。
  5. 把錯誤訊息與預期結果一起回填，要求只修正受影響部分。

如何驗收結果？

直接答案： 驗收不能只確認公式沒有錯誤或程式成功執行，還要核對資料範圍、計算規則、例外案例、輸出內容與必要權限。

  • 指定商品與付款狀態同時符合。
  • 整欄引用未把標題列當成資料。
  • 日期條件包含正確起訖日。
  • 新增資料後結果可以更新。

建議再做三層核對：第一層用兩至三筆資料手算；第二層比較來源總筆數與輸出總筆數；第三層測試空白、重複、未對應、期間外或權限不足等例外。

常見錯誤與限制有哪些？

直接答案： 最常見問題是欄位與指標未定義清楚、直接相信產出，以及忽略資料型態、權限、部署版本與工具規模限制。

  • 把 Excel 公式貼到 Google 試算表卻未確認支援差異。
  • 欄位位置寫錯，公式仍能執行但結果錯誤。
  • 看到沒有錯誤訊息就以為計算正確。

若工作涉及正式財務、法遵、薪資、交易、大量多人使用或高可用性要求，應加入正式審核、權限、測試、記錄與稽核機制，不能只依賴教學用試算表原型。

常見問題 FAQ

直接答案： 以下問答處理操作、驗證與工具選擇時常見的疑問；每個答案都可脫離前文單獨閱讀與套用。

QAI 可以直接幫我寫 Excel 公式嗎？

可以。應提供欄位名稱、條件、預期輸出與一小段虛構範例，並在 Excel 中驗證結果。

QSUMIFS 和 QUERY 有什麼差別？

SUMIFS 適合回傳單一條件加總；QUERY 適合分組、彙總與排序成一張動態表格。

Q可以把公司資料直接上傳給 AI 嗎？

不建議未經核准就上傳真實個資或機密資料。多數公式只需要欄位結構與虛構範例。

Q公式出現錯誤怎麼辦？

把錯誤訊息、公式、工具名稱與地區設定提供給 AI，並要求逐段檢查範圍與資料型態。

QGemini 產生的公式一定正確嗎？

不一定。Google 也提醒生成內容可能不準確，公式仍需抽查與測試。
