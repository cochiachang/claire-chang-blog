完整操作教學怎麼做？

直接答案： 完整操作從確認工具與資料結構開始，再依序設定規則、產出結果、測試例外並人工驗收。每一步都要保留可核對的輸入與輸出。

步驟 1：建立測試副本與成功條件

先複製原始檔，或建立只含欄位標題與三筆假資料的測試表。寫下「完成後應看到什麼」，例如公式回傳數字、試算表新增一列、雲端硬碟出現指定檔案，或 Dashboard 顯示可回扣的 KPI。

步驟 2：確認資料欄位與型態

逐欄核對工作表名稱、欄位標題、日期、文字、數字與唯一鍵。不要只依投影片中的欄位字母，因為實際檔案插入或刪除欄位後，位置可能不同。

步驟 3：依序完成核心工作

  1. 定義報告期間與 KPI 公式。
  2. 在 Google 文件放置明確變數。
  3. 由 Apps Script 計算指標與圖表資料。
  4. 複製樣板並取代所有變數。
  5. 轉成 PDF。
  6. 建立 Gmail 草稿並附加 PDF。

步驟 4：貼入完整 Prompt 並補上自己的資料位置

先把下方 Prompt 中的工作表名稱、欄位、網址、Spreadsheet ID、文件樣板、Email 或 MENU 替換成自己的測試資料。若需求涉及 Apps Script，要求輸出完整的 Code.gs 與 Index.html，不能只拿片段程式碼。

步驟 5：先小量執行，再擴大範圍

公式先用三至五筆資料測試；Apps Script 先用副本與自己的測試信箱執行；Web App 先送出一筆測試資料。確認結果正確後，再換成完整資料範圍。

步驟 6：依驗收清單核對與記錄例外

至少保留一個正常案例、一個邊界案例與一個錯誤案例。若結果不符，回頭檢查欄位名稱、資料型態、日期範圍、唯一鍵、權限與部署版本。

可直接複製的完整 Prompt

直接答案： 以下 Prompt 依投影片的六句提示法補齊目的、使用者、欄位、功能、規則與畫面或輸出。複製前必須替換自己的資料位置與測試條件。

① 我要做什麼
做一個「SnackFlow 每週營運週報自動化工具」，使用連結式 Google Apps Script，從「SnackFlow 每週營運資料」計算本週指標、產生圖表、套用 Google 文件樣板產生 Executive Report、轉成 PDF，並建立 Gmail 草稿。
② 給誰使用
給 SnackFlow 營運主管使用，報告對象是董事長；第一版只建立草稿，不直接寄出。
③ 有哪些欄位
資料包含日期、通路、商品名稱、品牌、商品分類、植物性（Yes／No）、購買數量、營收。需計算報告期間、本週營收、訂單數、總銷售商品數、平均客單價、熱銷品牌、熱門商品、植物性商品比例，並填入文件樣板變數。
④ 要哪些功能
新增自訂選單「週報自動化 → 一鍵產生 Executive Report」；讀取資料、計算 KPI 與圖表資料、使用 Charts Service 產生圖表、複製文件樣板、取代變數與圖表 Placeholder、轉成 PDF、建立 Gmail 草稿、加入收件人、主旨、內文與附件，完成後顯示通知。
⑤ 有哪些規則
報告期間＝本週資料起訖日；營收加總並顯示 $ 與千分位；訂單數＝本週資料筆數（若有訂單編號則改用唯一訂單數）；總銷售商品數＝購買數量加總；平均客單價＝營收÷訂單數；熱銷品牌＝品牌營收最高者；熱門商品＝購買數量最高者；植物性比例＝Yes 購買數量÷總購買數量，保留一位小數。
圖表：<RevenueTrendChart> 為每日營收折線圖；<ChannelChart> 為通路營收長條圖；<BrandChart> 為品牌營收 Top 10 橫條圖；<CategoryChart> 為分類營收圓餅圖；<PlantChart> 為植物性購買數量圓餅圖；<TopProductChart> 為商品購買數量 Top 10 橫條圖。所有變數與 Placeholder 必須取代。PDF 檔名為「SnackFlow Weekly Executive Report.pdf」，Gmail 主旨為「SnackFlow 每週營運週報」。
⑥ 畫面與交付
圖表置中且在 PDF 清楚可讀。請提供完整 Code.gs、樣板與資料網址替換位置、第一次執行授權，以及 KPI、變數、圖表、PDF、收件人、主旨與附件的逐項驗收清單。

Q如何使用這份 Prompt？

  1. 保留六個區塊，不要只複製第一句。
  2. 把範例中的工作表、欄位字母、網址、ID、Email 與日期換成測試資料。
  3. 要求先說明假設，再輸出公式或完整程式碼。
  4. 執行前檢查是否會寄信、分享檔案、覆寫資料或建立公開網址。
  5. 把錯誤訊息與預期結果一起回填，要求只修正受影響部分。

如何驗收結果？

直接答案： 驗收不能只確認公式沒有錯誤或程式成功執行，還要核對資料範圍、計算規則、例外案例、輸出內容與必要權限。

  • KPI 與試算表人工計算一致。
  • 所有樣板變數都已被取代。
  • PDF 圖表、日期與文字沒有截斷。
  • 收件人、主旨、期間與附件正確。

建議再做三層核對：第一層用兩至三筆資料手算；第二層比較來源總筆數與輸出總筆數；第三層測試空白、重複、未對應、期間外或權限不足等例外。

常見錯誤與限制有哪些？

直接答案： 最常見問題是欄位與指標未定義清楚、直接相信產出，以及忽略資料型態、權限、部署版本與工具規模限制。

  • 同一個 KPI 在試算表與文件使用不同定義。
  • 日期區間包含錯誤時區或少一天。
  • 第一版就直接自動寄出，沒有審核點。

若工作涉及正式財務、法遵、薪資、交易、大量多人使用或高可用性要求，應加入正式審核、權限、測試、記錄與稽核機制，不能只依賴教學用試算表原型。

常見問題 FAQ

直接答案： 以下問答處理操作、驗證與工具選擇時常見的疑問；每個答案都可脫離前文單獨閱讀與套用。

QApps Script 可以自動產生 PDF 嗎？

可以。Google 官方提供從試算表產生 PDF 並透過電子郵件傳送的自動化範例。

Q為什麼建議建立 Gmail 草稿而不是直接寄出？

草稿保留人工檢查收件人、數字、期間與附件的機會，適合作為低風險導入版本。

QGoogle 文件樣板怎麼設計？

用不容易與正文混淆的變數名稱，例如 ，並建立每個變數對應的 KPI 定義表。

Q圖表可以一起放進 PDF 嗎？

可以使用 Apps Script Charts Service 或試算表既有圖表，但需驗收尺寸、清晰度與資料範圍。

Q寄信有使用量限制嗎？

Apps Script 與 Gmail 具有每日配額，實際上限依帳號類型而異，部署前應查閱 Google 官方配額。
