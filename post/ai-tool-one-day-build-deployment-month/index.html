AI 一天寫完工具，為什麼上線卻卡了近一個月？一位資安分析師的部署卡關紀錄

資安分析師用 Claude 網頁版一天做完新聞彙整工具，卻花近一個月才讓同事開得起來。本文拆解卡關環節，補上 Vercel 與 GitHub Pages 的官方條款，並提供開工前的上線檢查表。

AI 幫你把網頁工具寫完，不代表同事就能打開它。我訪談的一位資安分析師，用 Claude 網頁版一天就完成資安新聞彙整工具的程式碼，卻花了近一個月才讓它真正上線。他卡住的不是寫程式，而是上傳 GitHub、串接部署平台、設定環境變數、處理權限與連線這些他從沒碰過的事。程式寫完不等於產品完成，所以在開始做之前，就該先想好它要怎麼上線，以及公司用的工具能不能用免費方案。

這位資安分析師想解決的是什麼問題？

資安分析師的團隊每天要逐一點開不同資安新聞網站，篩選與客戶環境相關的漏洞與事件再整理成報告，半天到一整天都耗在瀏覽與彙整，這是受訪者想解決的問題。

受訪者任職於資安產業，日常工作是監控客戶端的告警事件，判斷那是真正的攻擊還是系統誤判，並提供處理建議。在這樣專業的工作裡，有一項單純卻耗時的任務：資安情資與新聞收集。部分企業客戶需要定期掌握最新漏洞、攻擊手法與國際資安事件，團隊就得一個網站一個網站點開、閱讀、判斷、整理。

他沒有程式背景，也沒開發過任何系統，但想試試這件事是否真的需要人力逐篇閱讀。他的目標很明確：自動抓取幾個固定來源的資安新聞，集中顯示在同一頁，讓同事快速瀏覽後再決定要不要深入閱讀。

AI 一天就寫完的原型長什麼樣子？

受訪者用 Claude 網頁版，以日常語言描述需求，由 AI 反問細節、拆解功能並逐步產生程式碼與畫面，一天內完成能彙整多個資安新聞來源的網頁原型。

他形容那個過程很像跟專案經理討論需求：他說「我需要收集不同網站的資安新聞，想集中在同一個頁面，可以快速瀏覽標題與摘要」，AI 會追問細節，協助拆解功能，再往下生成。成果是一個可以管理新聞來源（匯入、匯出設定）並搜尋相關資安新聞的網頁。

上圖是工具的畫面：上方統計列顯示新聞總數與來源數，中間可以新增 RSS 來源、匯出或匯入設定，下方是彙整後的新聞卡片。截圖時的來源是 The Hacker News 與 Krebs on Security 兩個。

程式寫完之後，為什麼會卡將近一個月？

工具只在自己的電腦上能開，同事無法使用，必須把程式碼上傳 GitHub、串接部署平台、設定環境變數並處理權限與連線，這些他沒碰過的環節讓部署卡了近一個月。

他原本以為網頁做出來就完成了，很快發現沒有部署到伺服器，工具只能在自己的電腦上用。這是他第一次意識到：程式寫完不等於產品完成。完整流程還包括上傳 GitHub、串接部署平台、設定環境變數、處理權限與連線。

那段時間他幾乎每天做三件事：把錯誤訊息貼給 AI、向老師請教、在社群搜尋解法。他嘗試過的平台如下。

嘗試的平台他遇到的狀況
Azure需要付費，改試其他方案
GitHub Pages遇到靜態頁面的限制
其他平台持續出現各種錯誤訊息
Vercel在老師建議下改用免費部署，成功突破

最後走通的路線就是上圖這四步：Claude 網頁版產生程式碼，GitHub 存放原始碼，Vercel 負責部署與運行環境，產出可以在線上瀏覽的 App。每一步各有獨立的設定，這也是沒碰過的人會一路卡下去的原因。

GitHub Pages 與 Vercel 免費方案，適合放公司的內部工具嗎？

GitHub Pages 是靜態網站託管服務，不適合需要後端的工具；Vercel 的免費 Hobby 方案僅限非商業的個人使用，公司用途要先確認條款。

受訪者碰到的「靜態頁面限制」與免費方案，在官方文件裡都有明確規定。以下條款以 2026 年 10 月 19 日查閱的官方頁面為準，方案內容會調整，請以最新官方說明為準。

平台官方文件的規定
GitHub Pages定義為「靜態網站託管服務」，處理 HTML、CSS 與 JavaScript 檔案；發布的站台不得超過 1 GB，頻寬的軟上限為每月 100 GB，建置的軟上限為每小時 10 次，部署超過 10 分鐘會逾時；不打算也不允許當作免費主機來經營線上事業，也不應用於傳送密碼或信用卡號等敏感交易（GitHub Docs）
Vercel Hobby 方案限非商業的個人使用；商業使用需要 Pro 或 Enterprise 方案。官方對商業使用的定義，是任何為了「參與專案製作的任何人」的財務利益而使用的部署，包括撰寫程式碼的受薪員工或顧問（Vercel Fair Use Guidelines，最後更新 2026 年 9 月 14 日）

依 Vercel 的字面定義，受薪員工為公司撰寫的內部工具，有可能被視為商業使用。受訪者沒有說明他的工具是否屬於這種情況，本文也不判定他是否違反條款。如果你的工具是為公司工作而做，官方建議不確定時直接聯絡 Vercel 支援團隊確認，不要只憑「免費」就放上去。

開始開發前，要先確認哪些上線條件？

請 AI 寫程式之前，先確認誰會使用、工具是否需要後端或金鑰、程式碼放哪、費用條款、誰能存取，以及出錯時由誰查看，可以避免做完才發現無法上線。

下表是我根據這個案例與官方文件整理的檢查表，把他卡住的每個環節轉成開工前的問題。

開工前要問的問題為什麼要先問
誰會使用？只有自己、同一個團隊，還是對外公開？決定是否需要登入與權限控管
工具只有畫面，還是需要後端、資料庫或 API 金鑰？靜態託管服務只能放靜態檔案，需要後端時要選別的平台
程式碼放在哪裡？是否已建立 GitHub 帳號與儲存庫？多數部署平台從程式碼儲存庫取得內容
金鑰與設定值放哪？應在部署平台的環境變數中設定，不寫死在程式碼裡
費用與條款：是公司用途嗎？免費方案常限制商業使用，公司工具要先確認
公開網址能不能放這份資料？公開網址等於任何人都有機會看到，內部資料需要登入保護
出錯時誰查看紀錄？沒有人負責，工具壞了就會停擺

資安新聞彙整工具抓的都是公開資訊，放在公開網址上風險有限。如果工具處理的是客戶告警或內部報告，就不能照搬同樣做法，要先設計登入與權限。

一個沒有程式背景的人，從這次經驗學到什麼？

受訪者認為想做 Vibe Coding，不必先學程式語言，但要先理解開發流程與架構：需求如何拆解、系統如何運作、前後端如何分工、產品如何部署。

他有兩個觀察。第一，AI 很像員工：規格書越清楚，成果越接近預期；與人不同的是，AI 不會揣摩隱含的意思，只會精準執行被明確說出的內容。需求描述模糊，結果就模糊。第二，如果不使用一站式雲端平台（通常要付較高的費用），而是用本地端的開發工具，對開發架構的理解就無法外包。

能力內容
需求如何拆解把模糊的想法轉成清楚的功能需求，把大型目標拆成小任務，定義每個功能的輸入與輸出
系統如何運作資料如何儲存與讀取、功能之間如何互相影響，出錯時才能快速定位
前後端如何分工哪些功能在前端完成、哪些需要後端，以及兩者如何串接
產品如何部署上傳到伺服器、設定網域、連接資料庫、確保安全與權限管理

對他來說，Vibe Coding 最大的意義，是讓第一線工作者有機會自己打造工具，解決每天面對的實際問題。他表示工具上線後確實替團隊省下大量查找資安新聞的時間，這是他的自述。

工具寫完才發現資料不能放上公開平台，是上線卡關的常見原因。動工前可以先用這份資料能不能交給 AI？判斷資料的處理路徑，再用企業 AI 該用雲端還是自己架？確認公司適合雲端還是自行架設。需要有人在動工前一起盤點上線條件，可以參考AI 導入陪跑的需求訪談與 PoC 驗證；想自己動手、需要有人隨時解惑，則有1 對 1 AI 教練。

常見問題

QAI 寫好的網頁，要怎麼讓同事也能打開？

要把程式部署到伺服器或雲端平台。常見流程是先把程式碼上傳 GitHub，再串接部署平台，設定環境變數與權限，得到一個大家都能開啟的網址。受訪者最後用的是 GitHub 加 Vercel。

Q為什麼 AI 一天能寫完程式，部署卻要好幾週？

部署涉及帳號、平台設定、環境變數與權限，設定細節多、錯誤訊息不直覺，各平台規則也不同。AI 能協助排錯，但使用者仍要理解自己卡在哪一步。

QGitHub Pages 適合放 AI 做的工具嗎？

GitHub Pages 是靜態網站託管服務，適合純靜態頁面。如果工具需要後端或保管金鑰，就會遇到限制，受訪者就是在這裡碰壁。實際規定請看 GitHub 官方文件。

Q公司的內部工具，可以放在 Vercel 免費方案嗎？

要先確認條款。Vercel 的 Hobby 方案限非商業的個人使用，且定義包含受薪員工為公司撰寫的部署，不確定時官方建議聯絡支援團隊。公司用途較穩妥的做法是先看付費方案的條件。

Q內部工具放在公開網址安全嗎？

要看資料。工具只呈現公開資訊時風險較低；處理客戶資料或內部報告時，需要登入保護與權限控管，不能只靠網址不容易被猜到。
