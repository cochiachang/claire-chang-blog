產品體驗設計概念介紹

從 UX、HX、CX 到使用者需求、商業目標與數據分析，整理產品體驗設計的核心概念。

產品體驗設計不是只把介面做漂亮，而是讓使用者在接觸產品前、使用產品中、離開產品後，都能感受到功能可用、操作順手，也覺得這個產品對生活或工作有意義。這篇整理我上溫明輝老師「UX・三刀流」課程後留下的筆記，也把 UX、HX、CX、心智模型和 UXer 能力拆成比較容易回頭查的版本。

什麼是使用者體驗設計？

使用者體驗設計是一個以使用者為中心的設計過程，目標是改善人與產品或服務互動時的整體感受。使用者體驗設計同時處理功能性、操作性與情感體驗。

使用者體驗設計（User Experience Design，UX Design）關心的是「使用者完成目標的整段經驗」。介面美不美只是其中一小塊；真正要看的，是使用者能不能完成任務、過程會不會卡住、完成後是否覺得值得。

我覺得 UX 最容易被誤解的地方，就是把 UX 當成 UI。UI 是產品和使用者溝通的橋梁，包含資訊架構、圖示、按鈕、互動元件與畫面配置；UX 則要回頭問：這些設計有沒有真的幫使用者走到目標？

使用者體驗可以從哪些面向分析？

使用者體驗可以用時間軸和需求縱面一起分析。時間軸看互動前、中、後的感受，需求縱面看功能面、操作面與情感面是否同時被照顧。

時間軸的角度很好懂：閱讀一本書之前會有期待，閱讀過程會和內容展開對話，閱讀之後還會留下回想。產品也是一樣，使用者還沒打開產品前，就已經被名稱、介紹、評價、廣告或朋友推薦影響了。

需求縱面可以拆成三層：

面向要回答的問題常見判斷
功能面產品能不能滿足基本需求？使用者是否能完成任務
操作面產品是否容易上手？使用者是否知道下一步要做什麼
情感面產品是否帶來正向感受？使用者是否感到放心、愉快或有完成感

用訂餐 App 當例子，互動前的重點是讓使用者相信「不用出門也能享受美食」；互動中的重點是讓選單、購物車、付款、地址輸入都順利；互動後的重點是讓使用者覺得快速、方便，而且生活因此變得更輕鬆。

面向互動前互動中互動後
情感面在家訂餐讓時間更彈性自由付款與預約快速完成，不容易出錯對服務留下滿足感與好印象
操作面介面看起來不難操作從選單到地址輸入都能順利完成覺得整體流程簡單
功能面可以不用出門就享受美食餐點與選項能滿足當下需求願意下次再使用

HX、CX 和 UX 有什麼差別？

HX、CX 和 UX 的差別在觀察尺度不同。UX 看使用者與產品的互動，CX 看消費者與品牌商業元素的關係，HX 看產品對人群與社會的影響。

人類體驗設計（Human Experience Design，HX）比 UX 更宏觀，思考的是產品如何影響個人、群體，甚至社會文化。消費者體驗（Customer Experience，CX）則會把廣告、品牌信任、定價策略、客服流程等商業元素一起放進來看。

Clubhouse 語音社群 App 是一個很好理解的例子。產品初期透過名人與影響者創造話題，再用限量邀請機制製造稀缺感；使用者進入房間後，語音臨場感又帶來連結感與參與感。這不只是某個按鈕做得好不好，而是品牌、社群、稀缺性與互動形式共同塑造的體驗。

產品體驗設計成功的關鍵是什麼？

產品體驗設計成功的關鍵，是同時讓產品好用、能解決問題，並且讓使用者覺得有意義。只追求新技術或漂亮畫面，通常無法形成穩定採用。

好的產品體驗需要結合功能、操作與情感面。功能面解決「有沒有用」，操作面解決「會不會用」，情感面解決「還想不想再用」。三者缺一個，產品都可能卡住。

課程裡提到一個我很認同的轉變：《UX 策略》裡「殺手級的 UX 設計」被修訂為「無摩擦力的 UX 設計」。這個改法很有意思，因為好的設計不一定要讓人驚呼，而是讓人不必一直意識到設計存在。使用者能快速上手、無痛進入服務內容，產品才有機會被真的採用。

心智模型如何用在產品設計實作？

心智模型可以幫助設計者理解使用者以為產品會怎麼運作。產品設計要讓介面、資訊架構與互動回饋貼近使用者預期，再透過測試逐步修正。

心智模型不是抽象名詞而已。設計師實際在設計「物」的時候，會透過產品本身和溝通方式來創造體驗。使用者介面就是中間的橋，負責把產品邏輯翻譯成使用者看得懂、摸得到、能操作的形式。

設計不會一次就到位。比較務實的做法，是先提出假設，再讓使用者探索產品，觀察使用者在哪裡停住、哪裡誤解、哪裡覺得順。UX 設計在這個意義上很像一門科學：不是靠設計師覺得好，而是靠假設、驗證、回饋和迭代慢慢逼近更好的使用經驗。

產品研發流程中，UXer 通常會參與這幾個階段：

  1. 了解市場現況，確認商業目標與設計目標。
  2. 了解使用者需求，找出需求與設計機會。
  3. 設計人與電腦之間的溝通和互動，發展產品概念。
  4. 參與產品設計與研發實作。
  5. 做產品測試與設計評估，持續優化。

UXer 最需要哪些能力？

UXer 最需要 user flow、business flow 和 data flow 三種能力。使用者需求、商業分析與數據分析要一起看，產品設計才不會只滿足單一角度。

第一個能力是使用者需求，也可以理解成 user flow。UXer 要找出使用者真正想完成的事，串起使用者互動流程，讓使用者用最低阻力走到目標。這裡的重點不是問使用者「你想要什麼功能」，而是看使用者在什麼情境下遇到什麼問題。

第二個能力是商業分析，也就是 business flow。產品體驗不能只讓使用者開心，也要讓企業有理由繼續投入資源。企業有利可圖，產品才有機會持續被開發、維護、推廣，最後到達更多使用者手上。

第三個能力是數據分析，也就是 data flow。UXer 需要收集和解讀使用者行為資料，找出產品上線後該調整什麼。訪談和觀察能讓人理解原因，數據則能提醒團隊：問題發生在哪裡、規模有多大、改版後有沒有真的變好。

使用者需求和企業目標要怎麼平衡？

使用者需求和企業目標的平衡，是 UX 設計能不能落地的關鍵。產品必須同時讓使用者需求被滿足，也支持企業的商業策略與投入回報。

只站在使用者端看產品，容易做出很貼心但無法維持的服務；只站在企業端看產品，則可能做出指標漂亮但使用者不想用的流程。UXer 的工作，就是在兩邊之間找到可以長期成立的設計。

我會把這個平衡整理成三個檢查問題：

  1. 使用者是否真的需要這個產品，而不是團隊以為使用者需要？
  2. 使用者能不能不用太多學習成本，就開始體驗產品核心價值？
  3. 企業是否能從產品中得到足夠回報，讓產品持續改善？

真正好的產品體驗，不是把所有阻力都拿掉，而是把不必要的阻力拿掉。必要的步驟要清楚，不必要的等待要減少，容易出錯的地方要有提示，使用者才會覺得產品是站在自己這邊。

常見問題

QUX 設計和 UI 設計一樣嗎？

UX 設計和 UI 設計不一樣。UI 設計處理使用者看見和操作的介面，UX 設計則處理使用者完成目標時的整體經驗，包含功能、操作流程、情緒感受與使用後的印象。

Q產品體驗設計一定要做使用者研究嗎？

產品體驗設計需要使用者研究，否則團隊很容易只根據自己的想像做產品。使用者研究不一定一開始就很大型，可以先從訪談、觀察、原型測試和行為數據開始。

Q為什麼 UX 要同時看互動前、互動中和互動後？

使用者對產品的感受不是從打開畫面才開始，也不是按下完成按鈕就結束。產品名稱、介紹、朋友推薦、操作過程、完成後的回想，都會影響使用者是否願意再次使用。

QHX 和 CX 對產品設計有什麼幫助？

HX 可以提醒設計者思考產品對人群和社會的影響，CX 則讓設計者把品牌、定價、廣告、客服等商業接觸點放進來看。UX、HX、CX 一起思考時，產品比較不會只停在單一畫面或單一流程。

QUXer 為什麼需要懂商業分析？

UXer 需要懂商業分析，因為產品必須有足夠商業回報，才有機會持續開發和改善。好的使用者體驗不是和企業目標對立，而是要找到使用者價值與商業價值都成立的設計。

QUXer 為什麼需要懂數據分析？

UXer 需要懂數據分析，因為產品上線後不能只靠感覺判斷設計好壞。行為數據可以幫助團隊知道使用者在哪裡離開、哪個流程卡住，以及改版之後是否真的改善。
